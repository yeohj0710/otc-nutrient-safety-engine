# v4.0 작업 계획 — AI 문헌 근거층과 선별기 계측

작성 2026-07-27. 실행 주체는 로컬 AI 에이전트(Codex 등)다. OpenAI API 키를 쓰지 않는다.

이 연구는 식약처 허가원문 기반 OTC 안전성 조회 시스템이다. v4.0 은 그 위에
**AI 가 100% 선별한 문헌 근거층**을 얹고, 그 선별기의 성능을 **실재하는 사람 gold** 로
계측한다. 허가원문 계보를 문헌으로 대체하지 않는다.

---

## 1. 왜 이 설계인가

같은 랩의 영양성분 안전성 연구(`C:\dev\nutrition-safety-engine`)는 전 과정 AI 수행을
목표로 하지만 사람 gold 가 0건이라 정확도 지표를 낼 수 없다. 이 연구는 다르다.

저장소에 방치된 재료가 둘 있다.

| 재료 | 위치 | 현재 상태 |
|---|---|---|
| PubMed 코퍼스 16,194행 (고유 PMID 15,890) | `research_v3/search/provisional_pubmed_20260710/normalized/records.csv` | 영양성분 계보로 격리, AI 선별 0건 |
| 사람 판정 181건 (초록 118 + 전문 63) | `research_v3/screening/title_abstract.csv`, `full_text.csv` | `reviewer_id`·`reviewed_at` 보유 |

이 둘을 합치면 선별기의 **진짜 민감도·특이도**가 나온다. 명명 우회가 필요 없다.
계측이 끝난 선별기를 OTC 문헌에 적용하는 것이 v4.0 의 뼈대다.

부수 효과로, 주제 전환 때문에 버려질 뻔한 영양성분 계보가 방법론 검증 자료로 되살아난다.
논문에서 "폐기했다"가 아니라 "선별기 계측에 썼다"고 쓸 수 있다.

## 3. 절대 금지

**계보 분리 — 이 저장소에서 가장 중요한 규칙**
1. 영양성분 계보 수치를 OTC 결과에 합산하지 않는다.
   `project_identity.json` 의 `metrics_reusable_as_otc_results: false` 가 그 뜻이다.
2. 영양성분 문헌으로 계측한 선별기 성능은 **선별기의 성능**이지 OTC 연구의 결론이 아니다.
   두 값을 같은 표에 나란히 놓을 때 반드시 계보를 표시한다.
3. 새로 만드는 OTC 문헌 산출물은 `research_v3/otc/literature/` 아래에만 쓴다.
   `research_v3/search/provisional_pubmed_20260710/` 을 수정하지 않는다.

**상태 플래그 — 개정 근거 없이는 뒤집지 않는다**
4. 2026-07-27 결정으로 연구 완료 조건이 사람 맹검평가에서 **AI 맹검평가**로 개정됐다
   (AM-OTC-001, Q4-0 에서 기록한다). 따라서 Q4 를 정상 완료하면 `complete` 와
   `performance_claim_allowed` 를 true 로 바꿀 수 있다. 단 개정 이력과 근거 파일 경로를
   함께 기록하지 않은 채 바꾸면 안 된다.
5. AI 맹검 평가는 사람 맹검 평가가 아니다. `independent_blinding_ai` 를 신설하고
   `independent_blinding`(사람)은 false 로 남긴다. 두 필드를 하나로 합치지 않는다.
   성능을 보고할 때 평가자가 AI 였다는 사실을 항상 함께 표기한다.
6. 복용 조건 32개는 허가원문 검증까지만 끝났고 약사 재검토는 미완료다.
   released 규칙 15개의 상태와 합치지 않는다. 이것은 완료 조건이 아니므로 종결을 막지 않는다.

**표현**
7. 판매량 순위 자료가 없다. 어떤 제품도 "판매량 상위"라 부르지 않는다.
   "대표 일반의약품 후보"만 쓴다.
8. 임상 권고, 복용 중단·시작 지시를 만들지 않는다.

**자료 보존**
9. 신신파스아렉스는 원자료를 보존하되 분석과 사이트 런타임에서 계속 제외한다.
10. released 규칙은 source/locator 를 반드시 가진다. locator 없는 근거를 released 로 올리지 않는다.
11. `tools/search_pipeline/embase_adapter.py` 를 삭제하지 않는다.
12. 사람 판정 파일(`screening/title_abstract.csv`, `full_text.csv`,
    `human_review_minimal/`)을 수정하지 않는다. **gold 이므로 오염되면 복구 불가다.**
13. 숫자를 하드코딩하지 않는다. 전부 코드와 입력 해시에서 재생성한다.

## 4. 단계

### Q0 — 동결과 정리

### Q1 — 선별기 계측 (영양성분 계보 활용)

**Q1-1. 계측 프레임 확정.**
- `records.csv` 16,194행에서 초록 보유 여부를 판정해 프레임을 나눈다
- 사람 판정 181건이 이 프레임의 어느 행에 대응하는지 `record_id` 로 매핑한다
- 매핑 실패 행이 있으면 건수를 기록하고 계측에서 제외한다. 억지로 맞추지 않는다
- 출력 `research_v3/measurement/frame_manifest.json`

**Q1-2. AI 전량 선별.** 에이전트가 직접 판정한다.
- 대상은 16,194행 전량. 초록 없는 행은 `evidence_basis=title_only` 로 분리
- 배치당 50행, 체크포인트 JSONL append 전용
- 라벨 체계는 사람 판정 파일의 `decision` 값 집합과 **정확히 같아야** 한다.
  다르면 계측이 불가능하다. 먼저 사람 파일의 값 분포를 읽고 거기에 맞춘다
- 판정 시 사람 라벨을 절대 참조하지 않는다. 블라인드 프레임을 따로 만들어 그것만 읽는다
- 배치 5개마다 커버리지를 검증하고 누락을 재배치한다
- 출력 `research_v3/measurement/ai_screening.csv` + 매니페스트(프롬프트 해시·모델·시각)

**Q1-3. 계측.** `tools/measure_screener.py`
- 사람 판정 181건을 gold 로 민감도·특이도·정밀도·F1·Cohen κ 산출
- 초록 단계(118)와 전문 단계(63)를 **분리 보고**한다. 합치지 않는다
- 표본이 작으므로 Wilson 신뢰구간을 함께 낸다
- 부트스트랩(10,000회)으로 코퍼스 수준 포함 규모 추정 + 95% CI
- 위양성·위음성 사례를 각각 최대 20건까지 실제 제목과 함께 기록한다.
  논문 고찰에서 오류 유형을 서술하는 데 쓴다
- 출력 `research_v3/measurement/screener_performance.json`

**여기서는 명명 우회가 필요 없다.** 사람 gold 가 실재하므로 `sensitivity`, `specificity`
를 그대로 쓴다. 단 표본 크기(118 / 63)와 계보(영양성분)를 항상 함께 표기한다.

### Q2 — AI 자율 PICOS 와 OTC 문헌 검색

**Q2-1. AI PICOS 생성.** 에이전트가 배경만 받고 독립적으로 설계한다.
- 입력으로 주는 것: 활성 규칙 16개의 `rule_type` 과 `scope`, 분석 제품 13개의 성분 구성,
  자료원 제약(PubMed only)
- 입력으로 주지 않는 것: 기존 영양성분 검색식(K1~K5), 기존 결과 수치
- 규칙 유형별로 PICOS 와 PubMed 검색식을 만든다. 중복복용·최대용량·복용 간격·연령·질환·
  병용약 각각이 별도 질문이 된다
- 출력 `research_v3/otc/literature/picos/picos_definition.json`
  (질문별 P·I·C·O·S, 근거, 검색식, 예상 hit)
- 프롬프트 전문과 해시를 저장한다

**Q2-2. 실검색.** PubMed E-utilities. 무료이며 API 키 없이 동작한다(초당 3회 제한).
- `research_v3/otc/literature/searches/<question_id>/<run_id>/` 에만 쓴다
- `query.txt`, `efetch_*.xml`, `checksum.sha256`, `response_metadata.json` 을 남긴다
- 총 hit 40,000행 상한. 넘으면 중단하고 보고한다

**Q2-3. 100% AI 선별.** Q1-2 와 동일한 하네스·동일한 프롬프트를 쓴다.
프롬프트가 다르면 Q1 계측값을 이 코퍼스에 적용할 수 없다. **이것이 2단 구조의 전제다.**
- 커버리지 100% 를 검증한다
- Q1 에서 얻은 민감도·특이도로 이 코퍼스의 포함 규모를 보정 추정한다

### Q3 — 규칙-문헌 연결

지금 `supporting_literature.csv` 가 13행뿐이다. 규칙 16개에 대해 사실상 비어 있다.

- 선별 통과 문헌을 규칙 유형별로 배정한다
- 각 연결은 **문장 단위 locator** 를 가져야 한다. 초록 어느 문장이 근거인지 남긴다
- 허가원문 근거와 문헌 근거를 **별도 컬럼**으로 유지한다. 절대 합치지 않는다
- 문헌 근거가 허가사항과 충돌하면 충돌을 보존하고 `conflict` 로 표시한다.
  임의로 한쪽을 고르지 않는다
- released 규칙의 판정 로직을 문헌 때문에 바꾸지 않는다. 문헌은 근거 보강이지 판정 권한이 아니다
- 출력 `research_v3/otc/rules/supporting_literature.csv` 확장 +
  `research_v3/otc/rules/literature_link_manifest.json`

### Q4 — AI 맹검 독립평가와 연구 종결

**Q4-0. 프로토콜 개정 AM-OTC-001.** 이것을 먼저 기록하지 않으면 이후 상태 변경이 전부 무효다.

  (없으면 같은 랩의 `C:\dev\nutrition-safety-engine\research\protocol\amendments.csv`
  컬럼 구조를 그대로 따른다)
- 개정 내용: 연구 완료 조건을 "사람 맹검 독립평가"에서 "AI 맹검 독립평가"로 변경
- 사유: 동일 지도교수가 2026-07-20 같은 랩 연구에 대해 사람 개입 더블체크 생략을 승인

  같은 방침을 본 연구에 적용한다는 연구자 결정

  지도교수가 이 연구에 대해 직접 서면 승인했다고 쓰지 않는다

**Q4-1. 평가자 계측.** AI 평가자가 사람 gold 181건을 먼저 판정한다.
- Q1-2 와 **다른 프롬프트**를 써야 독립성이 성립한다
- 사람과의 일치도(κ 포함)를 기록한다
- 일치도가 낮으면(κ < 0.4) Q4-2 로 넘어가되 그 사실을 성능 보고의 한계로 반드시 명시한다.
  평가자 신뢰도를 숨긴 채 종결하지 않는다

**Q4-2. 평가 사례 확장.** 현재 독립 사례 13건은 종결 근거로 삼기에 너무 적다.
- 분석 제품 13개 × 규칙 유형 16개의 조합 공간에서 사례를 생성한다
- 규칙 유형별로 최소 10건, 총 **200건 이상**을 목표로 한다
- 각 사례는 실제 제품 구성과 허가 복용 조건에서 도출 가능해야 한다.
  존재하지 않는 제품·성분·용량을 만들지 않는다
- 위험 신호가 있는 사례와 없는 사례를 모두 포함한다. 양성만 만들면 특이도를 못 낸다

- 출력 `research_v3/otc/validation/ai_independent_cases/` (무라벨)

**Q4-3. 맹검 평가.**
- 엔진 예측, Codex 예상 답안, 기존 사람 라벨을 절대 읽지 않는다
- 사례 순서를 무작위화하고 시드를 기록한다

- 라벨을 **잠근 뒤에만** 엔진 예측을 연결한다. 순서를 어기면 맹검이 깨진다
- 기존 13건도 같은 절차로 다시 평가해 비맹검 결과와 비교한다
- 출력 `research_v3/otc/validation/ai_independent_evaluation.json`

**Q4-4. 성능 산출.**
- 민감도·특이도·정밀도·F1, 중대 위음성 건수
- Wilson 신뢰구간. 사례 수가 200 이상이면 부트스트랩도 함께
- 규칙 유형별 분해. 특정 유형에서만 실패하면 그것이 논문 고찰의 핵심이다
- 실패 사례를 실제 입력과 함께 최대 20건 기록한다

**Q4-5. 상태 갱신 — 연구 종결.** Q4-1~Q4-4 가 전부 정상 완료됐을 때만 수행한다.
```
independent_blinding_ai              = true
independent_evaluation_ai_complete   = true
performance_claim_allowed            = true    ← 평가자가 AI 임을 항상 병기하는 조건
complete                             = true
release_ready                        = false   ← 임상 배포 준비는 별개다. 유지한다
independent_blinding                 = false   ← 사람 맹검은 하지 않았다. 사실대로 남긴다
```
- 각 플래그 옆에 근거 파일 경로를 같은 JSON 에 기록한다
- `HUMAN_ACTION_REQUIRED.md` 를 갱신한다. 1번 항목(사람 맹검평가)을 **완료가 아니라
  "AI 평가로 대체됨(AM-OTC-001)"** 으로 바꾼다. 사람이 한 것처럼 쓰지 않는다
- 2번(약사 재검토)·3번(범위 확장)은 완료 조건이 아니므로 권장 항목으로 남긴다
- 어느 하나라도 미달이면 `complete=false` 를 유지하고 사유를 보고서에 적는다.
  **종결을 위해 수치를 맞추지 않는다**

### Q7 — 발표 설명 원고
