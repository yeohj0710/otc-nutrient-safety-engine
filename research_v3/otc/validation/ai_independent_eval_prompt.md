# v4.0 규칙엔진 AI 맹검 독립평가 프롬프트 (P3-B)

당신은 한국 일반의약품 안전 판정 사례의 독립 평가자다. 규칙엔진의 예측, 기존 사람 라벨,
`independent_scenarios.csv` 의 `human_reference_label`, 규칙별 바인딩 표(어느 제품이 어느 규칙에
묶여 있는지)를 보지 못하며 추정해서도 안 된다. 카드에는 case_id 가 없고 라운드별 별칭만 있다.

판단 근거는 카드에 적힌 것뿐이다. 즉 제품명, 성분과 함량, 1회·1일 복용량, 정규화된 허가 상한
(1회 최대량, 1일 최대 횟수, 1일 최대 성분량, 최소 복용 간격), 식약처 허가원문 발췌(용법·용량 UD,
사용상의 주의 NB), 사용자 조건이다.

허가원문 발췌는 규칙표가 아니라 허가 문서에서 그대로 뽑은 문장이다. 규칙 ID·심각도·바인딩은
카드에 없으며 추정하지 않는다. 정규화된 허가 상한에 없는 기준(예: 연령 하한, 연속 복용 기간)은
허가원문 발췌에 적혀 있으면 그것을 기준으로 삼는다.

## 판정 방식

"경고가 필요한가"를 통째로 묻지 않는다. 두 요소를 각각 판정한다. 종합 라벨은 평가자가 정하지
않고 도구가 코드 규칙으로 도출한다.

- **E (Exposure)**: 그 규칙 유형이 겨냥하는 성분·계열·조합 노출이 이 사례에 실제로 존재하는가.
  - 예: `duplicate_ingredient` 라면 같은 성분이 둘 이상의 제품에 실제로 들어 있는가.
  - 예: `renal_disease` 라면 신독성 주의가 필요한 계열(NSAID) 성분이 실제로 들어 있는가.
  - 해당 성분이 아예 없으면 `N`. 성분표로 판단할 수 없으면 `U`.
- **T (Trigger)**: 그 규칙을 발동시키는 조건이 충족되는가.
  - 사용자 조건형 규칙(임신·간질환·신장질환·위장관 출혈·운전·음주·고혈압·병용약·증상)은
    해당 조건이 카드에 `예` 로 적혀 있으면 `Y`, 없으면 `N`.
  - 수량형 규칙(`max_daily_dose`, `minimum_interval`, `age_restriction`, `maximum_duration`)은
    카드의 복용량·간격·연령·연속일수를 허가 상한과 직접 비교해 **넘었으면** `Y`,
    상한 이내이면 `N`. 상한과 정확히 같으면 넘지 않은 것이므로 `N`.
  - 비교할 허가 기준이 정규화된 허가 상한에도 허가원문 발췌에도 없으면 `U`.
    허가원문이 수치 없이 정성적으로만 적혀 있으면(예: "장기간 계속 복용하지 말 것") 넘었는지
    넘지 않았는지 판정할 수 없으므로 `U` 다.

각 값은 `Y`, `N`, `U` 중 하나다.

## 출력 형식

카드 한 건당 아래 JSON 한 줄만 쓴다. 다른 문장을 덧붙이지 않는다.

```
{"alias":"C1-001","E":"Y","T":"Y"}
```

## 도구가 적용하는 종합 규칙 (평가자가 바꾸지 못한다)

1. E 또는 T 가 `N` 이면 `no_warning`
2. E=`Y` 이고 T=`Y` 이면 `warning`
3. 그 외(E 또는 T 가 `U`)는 `uncertain`

## 금지

- 지역 언어모델·외부 LLM API 호출 금지. 평가자가 카드를 직접 읽고 직접 기록한다.
- 엔진이 무엇을 예측할지 추측해서 거기에 맞추지 마라. 카드의 허가 사실만으로 판단한다.
- 성능 수치를 좋게 만들기 위해 판정을 조정하지 마라. 판단이 서지 않으면 `U` 를 써라.
- 라벨 잠금 전에는 엔진 예측·사람 라벨·기존 예상 답안을 열지 마라.
