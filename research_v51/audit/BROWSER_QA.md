## 화면과 키보드

- 전체 시나리오와 최종 집중 회귀 모두 1440×1000과 390×844에서 `scrollWidth`가 viewport
  너비와 같아 가로 넘침이 없었다.
- 데스크톱 결과 패널 위쪽은 79.9375 px, 모바일은 79.546875 px였다. 두 화면에서 자동 이동 뒤
  결과 제목을 바로 읽을 수 있었다.
- 모바일 첫 Tab은 `본문 바로가기` 링크로 이동했고 2 px 실선 초점 표시가 나타났다.
- 첫 데모 버튼에 3 px 실선 초점 표시가 나타났고 Enter로 같은 중복 성분 결과를 실행했다.
- 건너뛰기 링크 실행 뒤 사이트 셸의 초점 이동은 목표 커밋과 분리된 사용자 미커밋 변경에
  속하므로 이 깨끗한 커밋 QA의 통과 항목으로 기록하지 않았다.

## 콘솔

- 오류는 0건이었다. 전체 시나리오에서는 같은 CSS preload 경고가 6회 발생했고, 최종 집중
  회귀의 두 세션에서는 합계 3회 발생했다. 고유 경고 유형은 모두 같은 1개였다. Next.js가
  생성한 CSS를 preload한 뒤 몇 초 안에 사용하지 않았다는 브라우저 경고였다. 판정 계산,
  상태 변경, 스크롤과 키보드 실행 중 애플리케이션 예외는 없었다.

## 결론

v5.1 목표 파일이 포함된 깨끗한 production build에서 정본 수치, 대표 판정, 지원하지 않는 범위,
미완성 복용량, 입력값별 지원 배지, 판정별 문헌 부재, 데스크톱·모바일 레이아웃과 키보드 실행을
확인했다. 모든 목표 시나리오가 통과했다. 이 QA는 임상 정확도나 사람 대상 사용성을 증명하지
않는다.
