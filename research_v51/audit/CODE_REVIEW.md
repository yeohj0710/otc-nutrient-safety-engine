# v5.1 독립 코드 리뷰 기록

## 리뷰 범위

기준 commit은 `6dbdad518e2fa7b2ed7b9a8048e0c47dba5b6ae9`다. 여러 독립 검토자가 기준 이후
v5.1 변경을 읽기 전용으로 나눠 검토했다. 검토 영역은 규칙 엔진·독립평가, 문헌 정책·UI,
연구 계보·감사 파이프라인이다. 검토자는 파일을 수정하거나 커밋하지 않았다.

이 문서는 리뷰에서 발견한 결함과 수정 검증을 기록한다. 리뷰 통과 자체는 임상 검증이 아니다.

## 규칙 엔진과 독립평가

수정 전 Important 결함은 3건이었다.

1. 타이레놀의 제품별 4,000 mg 상한에 다른 제품의 아세트아미노펜 입력량을 더해
   `OTC-RULE-003`을 만들 수 있었다. 제품별 허가 근거 범위를 넘는 판정이었다.
2. malformed 정책을 먼저 제거한 뒤 중복 rule ID를 찾았기 때문에, 정상 정책과 빈 적용 범위
   정책이 같은 ID를 쓸 때 정상 정책이 실행될 수 있었다.
3. 독립평가 입력 검사가 배열 길이만 확인해 중복 ID나 malformed 정책이 포함된 15개 배열을
   받아들일 수 있었다. 실제 엔진은 일부 정책을 제거하면서도 감사 수치는 15개라고 기록할 수
   있었다.

수정 상태: **수정 완료·원 검토자 재검토 통과**

- 제품별 1일 상한은 해당 제품 입력량만 계산하고, 성분 합계는 중복 성분 설명에만 사용한다.
- 중복 rule ID는 malformed 정책을 거르기 전에 원시 배열에서 찾고 같은 ID를 모두 제외한다.
- 독립평가는 규칙 수·고유 ID·실행 가능 정책·근거·공개 규칙 유형이 모두 일치해야 시작한다.
- 재검토: 집중 Vitest 108건, pytest 22건과 TypeScript 검사가 통과했고 남은
  Critical·Important 결함은 없었다.

## 문헌 분류와 결과 UI

수정 전 Important 결함은 3건이었다.

1. 직접 범위 배열이 모두 비어 있거나 boolean 자리에 truthy 문자열이 있어도 분류 검사가
   통과할 수 있었다. malformed 문헌을 직접 근거로 넓힐 가능성이 있었다.
2. 실제 결과가 배경 문헌으로 분류돼도 카드가 정책의 잠재적 직접 표시 능력을 제목으로 보여
   현재 결과와 모순될 수 있었다.
3. 첫 화면 집계가 실패 폐쇄 분류 검사를 재사용하지 않고 원시 JSON을 직접 읽어, 누락 분류에서
   빌드가 실패하거나 모순된 분류를 집계할 수 있었다.

수정 상태: **수정 완료·원 검토자 재검토 통과**

- 직접 표시 가능한 정책은 정확한 boolean과 비어 있지 않은 직접 범위를 요구한다.
- 문헌 카드는 정책의 잠재 능력이 아니라 현재 결과의 직접·배경 배치를 제목으로 표시한다.
- 첫 화면 집계와 결과 화면이 같은 실패 폐쇄 검사를 사용한다.
- 재검토: 집중 Vitest 56건과 TypeScript 검사가 통과했고 남은 Critical·Important 결함은
  없었다.

## 연구 계보와 감사 파이프라인

수정 전 Critical 결함은 2건이었다.

1. 보호 감사와 최종 감사가 변경 가능한 `baseline_manifest.json`의 commit·tree·해시를 그대로
   신뢰했다. 보호 대상과 manifest를 함께 바꾸면 새 상태를 기준선이라고 주장할 수 있었다.
2. 최종 감사가 입력 확인과 출력 쓰기 사이의 파일 변경을 다시 확인하지 않았고, 출력 파일의
   inode가 symlink·hardlink로 교체되는 경합을 막지 못했다. 계보가 오래되거나 보호 입력을
   덮어쓸 위험이 있었다.

수정 전 Important 결함은 4개 영역, 5건이었다.

1. 최종 감사가 신선도 스냅샷의 pinned semantic hash를 보호된 추출 문서에서 다시 계산하지
   않았다.
2. 전문가 검토 패킷 생성기가 triage 문구 안의 허위 승인·활성화 주장을 직접 차단하지 않았다.
3. 외부 제출 논문을 확인하지 못해도 보호 감사가 `valid=true`만 반환해, 로컬 검증과 전체 보존
   완료를 구분하지 못했다.
4. 신선도 감사의 CLI 출력 경로가 보호 파일이나 입력 파일을 가리킬 수 있었다.
5. 전문가 패킷 출력 경로에도 같은 경로·별칭 제한이 없었다.

수정 상태: **수정 완료·독립 재검토 통과**

- 기준 commit·`research_v3` tree·manifest 계약 digest를 감사 코드에 별도로 고정했다.
- 외부 논문 확인 여부를 `verification_complete`로 분리했다. 최종 감사의 기본 모드는 저장소
  내부 portable 경계만 검사하며 `final_local_report_ready=false`다. `--require-external` 모드는
  외부 정본 2/2까지 확인해야 `final_local_report_ready=true`를 반환한다. 두 모드는 같은 감사
  산출물 바이트를 계산한다.
- 최종 감사는 입력 identity·bytes·SHA-256을 출력 교체 직전에 다시 확인한다. 외부 정본은 같은
  열린 핸들에서 전후 `fstat`, 바이트, Windows 파일 identity와 경로를 다시 확인한다.
  `st_nlink=0`은 Windows 볼륨 정보가 hardlink 미지원 볼륨임을 확인한 경우에만 허용한다.
- 신선도 스냅샷은 보호된 추출 문서에서 의미 해시·문자 수·페이지 수를 다시 계산한다.
- 패킷과 신선도 감사는 정해진 출력 경로만 허용하고, 입력 별칭·symlink·hardlink를 거부한다.
- 전문가 패킷은 비활성 triage와 렌더 결과에서 허위 승인·활성화 주장을 검사한다.
- 이후 재검토에서 출력 파일을 차례로 닫는 늦은 교체 창, 정본 queue·triage와 패킷의 독립
  재구성 누락, 생성기·검증기 계보 누락, queue의 `reviewer_role` 누락, writer의 마지막 입력
  재검증 순서와 패킷 입력의 분리 읽기 창을 추가로 찾았다. 모두 수정하고 실제 파일 교체를
  주입하는 회귀 테스트를 추가했다.
- 최종 감사 writer는 staged 출력 descriptor 3개를 모두 잡은 상태에서 입력·경계를 다시 확인한
  뒤 출력 세트를 마지막으로 재검증한다. 제품 지원 행렬, 활성 규칙 행렬, `final_metrics.json`
  순서로 원자 교체하며 최종 수치 파일을 마지막에 게시한다. 세 파일 전체는 하나의 원자
  transaction이 아니다.
- 게시가 하나라도 시작된 뒤 실패하면 최종 감사는 자동 rollback이나 `unlink`를 하지 않는다.
  동시 writer의 데이터를 덮어쓰지 않도록 partial-publication 오류와 게시된 경로, 보존한 staged
  경로를 반환한다. 게시 전 실패도 staged 경로를 보존해 후속 확인이 가능하게 한다.
- 전문가 패킷 writer는 queue·triage·inventory·generator·validator 다섯 입력을 동시에 열린
  descriptor 세트로 캡처하고, 같은 바이트에서 행·감사 SHA·금지 패턴을 계산한다. 패킷이나
  감사 파일을 하나라도 게시한 뒤 실패하면 동시 writer의 파일을 덮어쓰거나 지우는 자동
  rollback·`unlink`를 하지 않고 partial-publication 오류와 보존한 staged 경로를 반환한다.
- 재생성 뒤 경계 감사는 `valid=true`, `verification_complete=true`, 외부 논문 2/2였다.
  Ruff·`py_compile`, 최종 감사의 portable·external `--check`도 통과했다.
- 마지막 독립 재검토는 입력·출력 inode 교체, 같은 inode 쓰기, 게시 뒤 쓰기와 staged 경로
  재사용을 다시 주입했다. 집중 회귀 8건과 독립 공격 회귀 9건이 통과했고, Critical·Important
  잔여 결함은 없었다. 최종 판정은 `Ready: yes`였다.

### 최종 후보 시나리오·원문 범위 재검토

- 추가 독립 감사에서 전문가 검토 후보 33건 중 26건의 회귀 시나리오가 후보 제품이 아니라
  참조 중인 기존 규칙의 실행 조건을 섞어 쓰는 문제를 발견했다.
- 회귀 시나리오 생성기는 이제 `shortlist_semantic_triage.csv`의 후보별 `proposed_trigger`와
  `expected_decision_ko`를 사용한다. 일반·경계·오탐 시나리오의 제품 코드는 후보 제품과 같고,
  비대상 시나리오는 성분이 겹치지 않는 실제 다른 제품만 허용한다.
- 어린이 용량표 문단의 `12.`가 닫히지 않은 괄호 안 소수점인데도 문장 끝으로 처리되어 원문이
  중간에서 잘리는 문제를 수정했다. `SAFE-OTC-05-UD-P1-B10-max_daily_dose`는 이제
  `용법용량 PDF p.1, 문단 10-17`과 마지막 `1~2세` 행까지 포함한다.
- 생성기·전문가 패킷 검증기·회귀 테스트에 후보 제품 코드, 후보 조건, 기대 판정과 완결 원문
  범위를 고정했다. 집중 테스트, 전체 Python 457건(2건 skip), Vitest 269건, TypeScript,
  ESLint, production build 157페이지와 외부 정본 포함 최종 감사가 통과했다.
